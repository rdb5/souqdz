# 🛍️ سوق دي زد — Souq DZ

ماركت بلايس جزائري رقمي، **بدون أي خادم أو قاعدة بيانات**، مبني بالكامل على بروتوكول
[Nostr](https://nostr.com) اللامركزي. هويتك = مفتاحك. بياناتك وإعلاناتك ورسائلك تعيش على
شبكة الريلايز (relays) العامة، لكن التطبيق يعرض فقط محتواه الخاص عبر وسم مخصص (`souq-dz-v1`)
فيبدو ويعمل كسوق مغلق تمامًا لمستخدميه.

## ✅ ما يتضمنه المشروع فعليًا

| الميزة | كيف تعمل تقنيًا |
|---|---|
| تسجيل الدخول | مفاتيح Nostr (إنشاء جديد / nsec موجود / إضافة NIP-07) |
| الإعلانات | أحداث `kind 30402` (معيار NIP-99) موسومة بوسم التطبيق |
| البحث والتصنيفات | فلترة الأحداث محليًا في المتصفح بعد الجلب من الريلايز |
| المحادثات | تشفير طرفي `NIP-04` — لا يُخزَّن نص الرسالة أبدًا إلا مشفّرًا على الريلاي |
| الإشعارات | تجميع أحداث (رسائل/طلبات) تخص مفتاحك العام + دعم Notification API للمتصفح |
| السلة | تخزين محلي في متصفحك (localStorage) فقط، يُمسح بعد إتمام الطلب |
| الطلبات | أحداث `kind 30403` مخصصة، محتواها مشفّر بين المشتري والبائع فقط |
| المحفظة | لا محفظة مركزية — دفع مباشر عبر Lightning Network (NIP-57 اختياريًا لاحقًا) |
| لوحة البائع | إحصائيات مبنية من إعلانات نفس المفتاح العام |

## 🚀 النشر على GitHub Pages خطوة بخطوة

1. أنشئ حسابًا على [github.com](https://github.com) إن لم يكن لديك واحد.
2. اضغط **New repository**، سمّه مثلاً `souq-dz`، اجعله **Public**، ثم أنشئه.
3. من صفحة المستودع، اضغط **uploading an existing file** وارفع كل الملفات والمجلدات
   الموجودة في هذا المشروع (حافظ على نفس أسماء المجلدات `css` و `js`).
4. بعد الرفع، اذهب إلى **Settings → Pages** (في القائمة الجانبية اليسرى).
5. تحت **Build and deployment → Source** اختر **Deploy from a branch**.
6. اختر الفرع `main` والمجلد `/root`، ثم اضغط **Save**.
7. انتظر دقيقة إلى دقيقتين، سيظهر لك رابط مثل:
   `https://<اسم-المستخدم>.github.io/souq-dz/`
8. افتح الرابط — تطبيقك يعمل مباشرة على الإنترنت لأي شخص! 🎉

> بديل أسرع: يمكنك أيضًا سحب وإفلات المجلد كاملًا في [Netlify Drop](https://app.netlify.com/drop)
> للحصول على رابط فوري بدون أي إعدادات.

## 🔐 ملاحظات أمان مهمة يجب قراءتها

- **مفتاحك الخاص (nsec) هو حسابك بالكامل.** لا يوجد "استرجاع كلمة مرور" — إن فقدته فقدت
  حسابك وإعلاناتك نهائيًا. التطبيق يعرضه لك مرة واحدة عند الإنشاء فقط.
- المفتاح يُخزَّن في `localStorage`/`sessionStorage` **داخل متصفحك فقط**، ولا يُرسل لأي خادم
  (لا يوجد خادم أصلًا). تجنّب استخدام حسابك على أجهزة عامة/مشتركة.
- التشفير المستخدم للمحادثات هو معيار `NIP-04` القياسي في Nostr. وهو تشفير طرفي حقيقي، لكنه
  ليس "غير قابل للكسر نظريًا" — لأمان أعلى مستقبلًا يمكن الترقية لمعيار `NIP-44` الأحدث.
- بما أن الشبكة عامة، الأحداث نفسها (حتى المشفرة) **مرئية الشكل** على الريلايز لأي شخص
  (يرى أنك أرسلت شيئًا، لا يرى المحتوى). الخصوصية الكاملة للميتاداتا تتطلب حلولًا إضافية
  (مثل NIP-59 Gift Wrap) يمكن إضافتها في تحديث لاحق.

## ⚡ حول الدفع

لا توجد بوابة دفع بنكية جزائرية (بريد الجزائر/CIB) مدمجة لأن ذلك يتطلب خادمًا خلفيًا وعقدًا
مع مزود دفع، وهو يتعارض مع مبدأ "بدون خادم/بدون قاعدة بيانات". البديل العملي المدمج هو الدفع
المباشر بين المشتري والبائع عبر شبكة **Lightning Network**، أو الاتفاق يدويًا عبر المحادثة
المشفرة (دفع عند الاستلام مثلاً)، وهذا ما تدعمه صفحة الطلبات حاليًا.

## 🛠️ تخصيص لاحق مقترح

- تغيير الريلايز الافتراضية من `js/nostr-client.js` (متغيّر `DEFAULT_RELAYS`).
- إضافة شعار حقيقي بدل الرمز التعبيري في الهيدر (`js/auth.js` → `renderShell`).
- ربط خدمة رفع صور خارجية (مثل nostr.build) بدل تضمين الصور كـ base64 داخل الحدث لتخفيف حجمه.
- تفعيل NIP-57 (Zaps) لدمج تنبيهات دفع Lightning حقيقية داخل صفحة المحفظة.
